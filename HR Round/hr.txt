Tell Me About a Challenging Production Issue
============================================
One challenging production issue I handled was related to user onboarding where newly invited users were not receiving invitation emails.
Since it was a high-priority issue, I first checked whether it was a configuration issue or a code-level issue. 
I analyzed the application logs and found that the workflow was failing due to a NullPointerException.

After further investigation, I identified that the invitation email template was not configured for that particular tenant. 
Because the system expected the template to exist, the workflow execution failed and the email was not triggered.

To resolve the immediate issue, I asked the client to configure the required template so they could continue inviting users. 
For the permanent fix, I modified the code to handle this scenario more gracefully by adding null checks 
and implementing a fallback mechanism where the system uses a default template if a tenant-specific template is not available.

This prevented the workflow from breaking in such cases and improved the stability of the onboarding process.

Explain Your Microservices Architecture
========================================
Our platform follows a microservices architecture where each service is responsible for a specific business capability 
such as record management Core-Crud, core-ui, workflows, notifications, sync and user management.

The frontend is built using Angular, which interacts with backend APIs developed using Spring Boot.

These backend services are designed as independent microservices that communicate with each other. 
For synchronous communication, we use gRPC when one service needs an immediate response from another service and Rest Endpoint. 
For asynchronous and event-driven communication, we use RabbitMQ.

The system stores data in PostgreSQL, and the platform is designed as a multi-tenant system where data is segregated using tenant identifiers.
And to get the data fastly we used the Elastic Search for the searching query.

This architecture allows us to independently scale services, deploy updates faster, 
and isolate failures without affecting the entire system.
